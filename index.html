Overview

Webfilter is a Chrome extension developed for use in Swedish schools and educational environments. Its sole purpose is to block access to websites that are inappropriate or unproductive during school hours.

This privacy policy explains what data Webfilter does and does not handle. The short answer: Webfilter collects no data whatsoever about users or their browsing activity.

Data we do not collect

Webfilter does not collect, store, transmit, or analyse any information about users or their browsing activity. All rule evaluation is performed locally in the browser by Chrome's built-in engine — the extension itself never has access to the content of any request or any webpage.

  • No browsing history is created or stored
  • No personal data is processed
  • Nothing leaves the device
  • No cookies, localStorage, sessionStorage or IndexedDB are written based on user activity
  • No tracking, analytics, telemetry or reporting of any kind
  • No third-party services, advertising libraries or external SDKs are included

How the extension works

Webfilter uses Chrome's built-in declarativeNetRequest API. All blocking rules are stored as static JSON files packaged directly inside the extension and evaluated locally on the device. No calls are made to external servers, APIs or cloud services.

When a user attempts to navigate to a blocked website, the browser tab is redirected to a built-in page (blocked.html) that is included in the extension package. This page informs the user that the site is restricted by the administrator. No external server is contacted during this process.

The rule list can only be updated by publishing a new version of the extension via the Chrome Web Store and distributing it through enterprise policy. There is no mechanism for remote rule updates, no push system, and no way to change the extension's behaviour without installing a new package.

Administrator configuration

IT administrators may optionally define a list of additionally allowed domains via Google Workspace's managed storage policy (allowedDomains). This configuration is read-only by the extension — nothing is written back. No user data is involved in this process.

Permissions

The extension requests exactly three permissions. No other permissions are requested or used.

declarativeNetRequest
Required to register static blocking rules and let Chrome's built-in rule engine redirect or block matched network requests. The extension never reads request content.
storage
Used exclusively to read administrator-configured policy from chrome.storage.managed. Nothing is written to storage by the extension.
host_permissions: <all_urls>
Required by the declarativeNetRequest API to evaluate blocking rules against outgoing requests to any domain. Does not give the extension access to page content, cookies or user data.

Regulatory compliance

Because no personal data is processed in any form, Webfilter does not trigger the compliance requirements of applicable data protection law. The extension is consistent with:

EU GDPR (Regulation 2016/679)

Art. 4, 5, 6, 9, 25, 30, 32, 35, 44–49 — no personal data is collected, so no lawful basis, DPIA, or data processing agreement is required.

ePrivacy Directive (2002/58/EC)

Art. 4, 5, 6, 9, 13, 14, 15 — no cookies are set, no electronic communications are intercepted or stored.

NIS2 Directive (EU 2022/2555)

Art. 2, 6, 20, 21, 23, 24, 32–33 — the extension introduces no vulnerabilities or data flows into the school's IT environment.

Swedish Education Act (Skollagen 2010:800)

Ch. 5 §§ 5–6, Ch. 6 §§ 1–6, Ch. 26a §§ 2–6 — no pupil data is handled; no data processing agreement is required for normal school use.

UN Convention on the Rights of the Child (UNCRC)

Art. 16 — children's right to privacy. The extension does not monitor, track or record children's activity. In force in Sweden since 2020.
